# 클래식: 범죄와의 전쟁

친구와 각자 사냥하고, 성장 기록과 전체 채팅을 함께 나누는 PC 웹 2D RPG입니다.
**제작자 : 예수**

독립적인 싱글플레이입니다. 캐릭터 위치, 몬스터, 전투는 다른 플레이어와 공유하지 않습니다. 온라인에서는 계정별 캐릭터 저장·공용 랭킹·전체 채팅을 제공합니다. 외부 서비스를 연결하지 않아도 로컬 데모로 이동, 전투, 강화, 상점을 사용할 수 있습니다.

## 1. 가장 먼저 게임 실행하기

필요한 프로그램은 **Node.js 22 이상**(24 권장), 최신 Chrome 또는 Edge, 이 저장소입니다.

1. 저장소 폴더에서 터미널을 엽니다.
2. 처음 한 번 `npm ci`를 실행합니다.
3. `npm run dev`를 실행합니다.
4. 같은 컴퓨터의 브라우저 주소창에 `http://localhost:3000`을 입력합니다.
5. **계정 없이 로컬 데모 체험하기**를 누르고 기사 또는 요정을 선택합니다.

```bash
npm ci
npm run dev
```

WASD/방향키로 이동하고 몬스터를 클릭하면 사거리까지 접근해 공격합니다. 직접 이동하면 대상 공격을 멈춥니다. `I` 인벤토리, `E` 강화, `B` 상점, `R` 랭킹, `M` 지도, `H` 도움말, `ESC` 창 닫기입니다. 물약은 화면 버튼 또는 숫자 1~4로 사용합니다. 채팅은 Enter로 입력하며, 입력 중에는 이동 단축키가 작동하지 않습니다.

처음에는 아데나 2,000, 강화주문서 8장, 빨강 25개, 주홍 10개, 초록 1개를 지급합니다. 초록 물약은 사용해야 공격속도가 증가합니다. 시작 지점 나무 간판에는 `자~~ 드가자~~~!`와 `제작자 : 예수`가 표시됩니다.

**로컬 데모**는 현재 브라우저에만 저장됩니다. 저장 키는 `classic-beomjae-demo-v1`이며, 다른 컴퓨터로 옮겨지거나 실제 랭킹에 등록되지 않습니다. 브라우저 데이터 삭제 시 데모도 사라집니다. **온라인 캐릭터**는 아래 Supabase 연결 후 계정별 데이터베이스에 저장되므로 다른 컴퓨터에서도 이어할 수 있습니다.

## 2. 온라인 계정·저장·랭킹·채팅 연결하기

현재 저장소에 실제 서비스의 키는 포함하지 않았습니다. Supabase 프로젝트를 만들고 아래 값을 직접 설정해야 합니다. 비밀 키를 채팅에 보내거나 GitHub에 올리지 마세요.

### Supabase 만들기

1. [Supabase](https://supabase.com/)에서 프로젝트를 만듭니다.
2. 프로젝트의 **SQL Editor**를 엽니다.
3. 다음 파일을 **번호 순서대로 각각 전체 실행**합니다.
   - `supabase/migrations/001_game.sql`: 계정별 게임 상태, 요청 중복 방지, 공개 랭킹
   - `supabase/migrations/002_chat.sql`: 전체 채팅 기록, 도배 제한, 접속자 정보, 시스템 알림
   - `supabase/migrations/003_monster_kills.sql`: 누적 몬스터 처치 수와 랭킹 확장
4. 프로젝트 설정의 API 항목에서 프로젝트 URL과 `anon` 공개 키, `service_role` 서버 전용 키를 확인합니다. 기존 JWT API 키 항목에 표시되는 키를 사용합니다.
5. `.env.example`을 복사해서 **`.env.local`** 파일을 만들고 값을 채웁니다.

```dotenv
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
```

빈칸에는 해당 프로젝트의 실제 값을 입력합니다. `SUPABASE_SERVICE_ROLE_KEY`에 `NEXT_PUBLIC_`를 붙이면 안 됩니다. 이 키는 브라우저에 노출되면 안 되는 서버 비밀 키입니다. `.env.local`은 Git에서 제외되어 있습니다.

6. Supabase의 **Authentication → Providers → Email**을 활성화합니다. 이메일 확인을 사용한다면 가입 확인 메일의 링크를 누른 후 로그인합니다.
7. **Authentication → URL Configuration**에 개발 중에는 `http://localhost:3000`, 배포 후에는 실제 게임 주소를 Site URL/허용 Redirect URL로 설정합니다.
8. 개발 서버를 중지하고 `npm run dev`로 다시 시작합니다. **캐릭터 생성 / 로그인**으로 가입하고 캐릭터를 만듭니다. 계정당 하나의 캐릭터이며 직업은 이후 변경하지 않습니다.

기존 데이터베이스에 001·002를 이미 설치했다면 **003만 추가 실행**하면 됩니다. 처치 수 항목이 없던 기존 캐릭터는 0부터 집계합니다. 과거 처치 기록을 추측해서 채우지 않습니다. 데이터베이스 초기화는 필요하지 않습니다.

### 전체 채팅 설정과 동작

Supabase Realtime이 활성화된 프로젝트에서 사용합니다. `002_chat.sql`은 `realtime.messages`에 비공개 채널 권한을 설정합니다. 채널명은 `classic-world-chat`입니다. `game_states` 테이블을 Realtime publication에 넣지 마세요. 이 게임은 데이터베이스가 발행하는 **Broadcast**와 접속자를 위한 **Presence**만 이용합니다.

- 로그인한 캐릭터가 하나의 전체 채팅방에 참여합니다. 여러 탭으로 접속한 동일 계정은 한 명으로 표시합니다.
- 최근 100개 메시지(사용자 및 시스템 합산)를 보관하고 재접속 시 읽어옵니다.
- 메시지는 1~300자, 2초에 한 번 전송 가능합니다. 닉네임은 서버 저장값을 사용합니다.
- +9/+10 강화 성공, 90/99레벨 달성 알림을 서버가 발행합니다. +10은 황금색으로 표시됩니다.
- 채팅은 별도의 연결과 재시도 절차를 사용합니다. 연결 오류가 나도 게임의 이동·전투 요청은 계속 처리됩니다.
- 화면 오른쪽 아래에서 채팅창을 접거나 펼칠 수 있습니다. 로컬 데모에는 온라인 채팅이 연결되지 않습니다.

Supabase 키와 실제 프로젝트가 연결되기 전에는 여러 실제 계정 간 로그인·채팅·Presence 전달을 검증할 수 없습니다. 아래 테스트는 로컬 게임과 서버 로직 및 SQL을 검증하며, 실제 호스팅 연결 검사는 별도로 수행해야 합니다.

## 3. 친구에게 주소 전달하기 — Vercel 배포

이 작업에서 배포나 환경 게시를 자동 수행하지 않습니다. 공개 주소는 다음 절차를 마친 후 생성됩니다.

1. 완성된 파일을 본인의 GitHub 저장소에 저장합니다.
2. [Vercel](https://vercel.com/)에서 **Add New → Project**로 `ideal-memory`를 연결합니다.
3. Framework Preset은 Next.js, Node 버전은 24, 빌드 명령은 `npm run build`를 사용합니다.
4. Vercel의 **Environment Variables**에 위 환경변수 3개를 등록합니다. 서버 전용 키를 공개 변수로 등록하지 마세요.
5. Deploy를 실행합니다. 환경변수를 바꾸면 다시 배포해야 합니다.
6. 생성된 HTTPS 주소를 Supabase의 Site URL/Redirect URL에도 등록합니다.
7. 두 개 이상의 실제 계정으로 아래 온라인 확인 절차를 마친 뒤 친구에게 주소를 전달합니다.

Vercel 서버는 Supabase에 저장된 상태를 읽고 검증한 다음 트랜잭션으로 갱신합니다. 실행 중인 서버 메모리에 캐릭터를 의존하지 않습니다. 플레이 중 약 0.2초 간격으로 요청하므로 요금제의 함수 실행량·데이터베이스 사용량을 확인하세요. 작은 친구 모임을 위한 초기 구조이며 대규모 동시접속용 서버는 아닙니다.

## 4. 실제 구현한 기능

- 기사/요정, 독창적인 픽셀 캐릭터·몬스터, 걷기/공격/피격/사망 이펙트, 네 사냥터, 장애물 충돌, 자동 접근·공격, 비선공/선공 AI와 재생성
- 서버 판정 경험치·아데나·주문서 보상, 1~99 성장, 30/60/90 자동변신, 99레벨 전체 처치
- +0~+10 강화, 명시된 강화 확률, 실패 시 +3, 무기와 방어구 동기화, 상위 지역 조건 상실 시 귀환, +10 직업별 특수 공격
- 물약 구매/사용, 초록 물약 서버 시간 10분·공격속도 2배, HP 80% 기준 자동 물약, 사망 무손실 귀환
- 계정 인증, 서버 저장/불러오기, 종합·레벨·무기 랭킹, 역대 최고 강화, **몬스터 처치 수**
- 독립적인 전체 채팅, 최근 기록 100개, 접속자 표시, 도배 제한, 서버 시스템 알림
- 로컬 데모, 단축키/버튼, 확률표·지도·도움말·인벤토리·상점·강화창·시스템 로그

몬스터 처치 수는 모든 사냥터의 누적 합계입니다. 실제로 살아 있던 몬스터가 사망으로 전환될 때 한 번 증가합니다. 광역 공격은 실제 처치된 수만큼 증가하며, 사망·지역 이동·재접속으로 초기화되지 않습니다. 보상과 동일한 트랜잭션으로 저장하고 중복 요청은 재집계하지 않습니다. 랭킹 가장 오른쪽에 표시하며 **종합 정렬은 기존 전투력(레벨×100 + 강화×1000)을 그대로 사용**합니다.

현재 준비되지 않은 외부 작업은 실제 Supabase 프로젝트/키 연결, 실제 이메일 가입 확인, 인터넷 배포, 여러 실제 기기에서의 최종 연결 확인입니다. 로컬 검증 통과를 실제 서비스 배포 완료로 간주하지 않습니다. 음악·모바일 터치 조작·실시간 공동 사냥/PvP는 제공하지 않습니다.

## 5. 테스트와 밸런스 확인

```bash
npm test             # 엔진, 서버 검증, 실제 PostgreSQL(PGlite) SQL/권한/동시 요청 테스트
npm run typecheck    # TypeScript 검사
npm run build        # 배포용 빌드
npm run balance      # 실제 전투 엔진을 사용하는 성장·처치시간·물약 소비 시뮬레이션
npm run test:e2e     # 브라우저에서 데모 생성/이동/전투/강화/저장/랭킹 UI 확인
```

브라우저 테스트에는 Chromium이 필요합니다. 시스템 Chromium이 없으면 먼저 `npx playwright install chromium`을 실행하세요. 별도 경로의 브라우저는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 지정할 수 있습니다. Playwright는 개발 서버를 자동 실행하며, 이미 실행 중인 3000번 포트의 서버를 재사용할 수 있습니다.

밸런스 도구는 정해진 레벨·장비에서 반복 전투하여 예상 시간을 출력합니다. 순수 사냥의 목표는 1~30 약 1시간, 30~60 약 2시간, 60~90 약 4시간, 90~99 약 6시간입니다. 강화 복구, 사망, 휴식, 실제 플레이어의 이동 방식과 네트워크 지연은 별도입니다. 시뮬레이션 결과와 실제 장시간 플레이는 구분해야 합니다.

### 서비스 연결 후 확인할 항목

1. 별도 브라우저/컴퓨터 두 곳에서 다른 계정으로 가입하고 기사·요정을 만듭니다.
2. 사냥·구매·강화 후 새로고침하고 같은 계정으로 다른 컴퓨터에서 접속해 저장된 상태와 처치 수를 확인합니다.
3. 로그인하지 않은 창에서도 랭킹·확률표가 열리고, 데모가 공용 랭킹에 포함되지 않는지 확인합니다.
4. 두 계정에서 Enter로 채팅하고 상대 메시지·시간·접속자 목록을 확인합니다. 빠른 연속 전송은 차단되어야 합니다.
5. 새로고침 후 최근 기록을 확인하고, 한 계정의 여러 탭이 접속자 수에 중복 표시되지 않는지 확인합니다.
6. 브라우저의 네트워크 도구에서 **Realtime 연결만** 끊고 이동과 전투가 계속되는지 확인합니다. 전체 네트워크를 끊으면 온라인 전투 저장도 불가능하므로 다른 검사입니다.
7. 시스템 메시지는 일반 사용자가 위조할 수 없어야 합니다. 실제 서비스 테스트를 위해 프로덕션 캐릭터를 임의로 고레벨로 변경하지 마세요. 해당 분기는 자동 SQL/엔진 테스트에서 검증합니다.

## 6. 게임 수치 바꾸기

`src/game/config.ts`의 한국어 주석을 참고하세요. `ENHANCE_CHANCES`는 0~1 확률, `ATTACK_BONUS`/`ARMOR_BONUS`는 강화별 능력치, `MONSTERS`는 HP·공격·속도, `ZONES`는 보상·입장조건·드롭률, `POTIONS`는 가격·회복량입니다. `GROWTH_STAGES`와 `XP_TABLE`은 성장 구간과 레벨별 경험치를 관리합니다.

변경 후 `npm test`, `npm run balance`, `npm run build`를 실행합니다. 온라인 판정도 같은 파일을 서버에서 사용하므로 변경값은 서버 재배포 후 적용됩니다. 이미 저장된 몬스터의 HP 등 기존 상태는 자동으로 재조정되지 않을 수 있습니다. 운영 중 수치 변경은 저장 데이터 호환성도 확인해야 합니다.

## 7. 코드 구조와 데이터 보호

```text
src/game/             공통 설정, 게임 상태, 서버 판정 가능한 순수 전투 엔진
src/art/              오리지널 픽셀 스프라이트와 지형 렌더링
src/components/       게임 화면, Canvas, 전체 채팅
src/app/api/          로그인 검증, 게임 명령, 공개 랭킹
src/server/           요청 검증, 서버 전용 Supabase 연결, 동시 요청 처리
src/lib/              브라우저 인증, 게임 요청, 채팅 도우미
supabase/migrations/  실제 SQL 스키마, RLS/권한, 트랜잭션, 채팅, 처치 수
scripts/balance.ts    반복 전투 밸런스 도구
tests/                엔진·서버·SQL·채팅 자동 테스트
e2e/                  실제 브라우저 조작 테스트
public/art/           오리지널 메인 화면 배경
```

렌더링은 Canvas 2D와 직접 구성한 픽셀아트를 사용합니다. Next.js/TypeScript, Supabase Auth·PostgreSQL·Realtime을 사용하며 Phaser는 필수 의존성으로 넣지 않았습니다. 외부 게임에서 추출한 그래픽·음악을 사용하지 않습니다. 리소스 교체 위치는 `src/art`와 `public/art`입니다.

온라인 클라이언트는 이동 방향/대상 ID/구매 종류 같은 명령만 보냅니다. 레벨·보상·시각·강화 성공 여부·계정 ID를 전달해 덮어쓸 수 없습니다. 서버는 토큰을 검증하고 서버 시간과 안전한 난수로 판정합니다. 상태 버전 비교와 행 잠금, 요청 영수증, 요청 빈도 제한으로 중복 소비·중복 보상·중복 처치 집계를 방지합니다. 오프라인 시간에는 자동 사냥 보상이 발생하지 않습니다.

`game_states` 등 비공개 테이블은 RLS와 권한 회수로 브라우저에서 읽거나 쓸 수 없습니다. 공개 랭킹에는 닉네임과 게임 통계만 노출하며 계정 UUID/이메일은 노출하지 않습니다. 채팅은 인증된 전용 SQL 함수만 작성할 수 있고, 클라이언트가 시스템 Broadcast를 직접 발행할 권한은 없습니다.
