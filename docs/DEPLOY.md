# 설치 없이 인터넷에서 게임 열기

기존 게임 주소: **https://ideal-memory-cyan.vercel.app**

이미 GitHub 저장소와 Vercel을 연결했다면 `main`의 새 커밋으로 자동 배포가 시작됩니다. Vercel에서 최신 배포가 **Ready**인지 확인하고 게임을 새로고침하세요. 아래 처음 연결 절차를 다시 진행할 필요는 없습니다.

## 처음에는 데모부터 공개하기

1. https://vercel.com/signup 에서 **Continue with GitHub**를 누릅니다.
2. 개인 용도라면 **Hobby** 플랜을 선택합니다.
3. https://vercel.com/new 에서 GitHub 저장소 **bestbay1402/ideal-memory** 옆 **Import**를 누릅니다.
4. 저장소가 보이지 않으면 **Configure GitHub App**에서 해당 저장소 접근을 허용합니다.
5. Framework는 **Next.js**, Root Directory는 그대로, Node.js는 **24.x**로 설정합니다.
6. Environment Variables는 우선 비워두고 **Deploy**를 누릅니다.
7. 완료 화면의 **Visit**를 누릅니다. 표시된 `https://…vercel.app` 주소가 게임 접속 주소입니다.
8. 게임 화면에서 **계정 없이 로컬 데모 체험하기**를 누릅니다.

이 주소는 인터넷에서 열리며 친구에게 전달할 수 있습니다. 데모 저장은 각자의 브라우저에 남습니다.
친구가 로그인 화면을 요구받는다면 Vercel 프로젝트 **Settings → Deployment Protection**을 확인하고, 공유할 Production 배포의 접근 제한을 해제하세요. 프로젝트 설정에 따라 미리보기 배포 주소는 로그인 보호가 켜져 있을 수 있습니다.

## 계정·랭킹·채팅 켜기

README의 Supabase 연결 절차를 완료하고 Vercel 프로젝트 **Settings → Environment Variables**에 실제 값을 등록합니다.

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` (서버 비밀 키)

데이터베이스 SQL은 `001_game.sql`, `002_chat.sql`, `003_monster_kills.sql` 순서로 실행합니다.
환경변수를 저장한 뒤 Vercel에서 **Redeploy**합니다. Supabase의 로그인 주소 설정에도 실제 게임 주소를 등록합니다.

Vercel 가입/승인과 실제 서비스 키 입력은 계정 소유자가 직접 진행해야 합니다. 비밀번호나 서비스 비밀 키를 채팅 또는 GitHub에 올리지 마세요.

## 회원가입 연결이 안 될 때

게임 주소 뒤에 `/connection`을 붙여 엽니다. 예: `https://게임주소.vercel.app/connection`.
페이지가 현재 서버 설정으로 주소, 공개 키, 서버 저장 키, 인증 서버, 게임 데이터베이스를 자동 검사합니다.
**확인 결과 복사**를 누르면 비밀 키가 포함되지 않은 진단 결과를 공유할 수 있습니다.

브라우저의 Supabase 도메인 직접 연결 문제를 줄이기 위해 인증 요청은 같은 게임 주소의 `/api/auth`를 통해 전달합니다.
프로젝트 주소가 잘못되었거나 프로젝트가 중지된 경우에는 해당 설정의 수정이 필요합니다.
기존 Supabase 이메일 확인·비밀번호 검증·요청 제한은 그대로 적용됩니다.
채팅의 Realtime 연결은 Supabase에 직접 연결하므로 브라우저 네트워크가 이를 차단하면 채팅은 별도로 연결에 실패할 수 있습니다.

## 10분 저장 방식 업데이트

`001_game.sql`부터 `003_monster_kills.sql`까지 설치된 기존 서비스에는 **추가 SQL이나 새 API 키가 필요하지 않습니다.** 기존 환경변수를 유지한 채 새 코드를 배포합니다. 이번 변경은 Vercel 함수 실행 지역을 `icn1`(서울)로 지정하며 Supabase 데이터베이스의 지역은 변경하지 않습니다.

업데이트 후 로그인하여 다음을 확인하세요.

1. 이동·공격이 데모처럼 바로 반응합니다. 이동마다 서버 응답을 기다리지 않습니다.
2. 상단에 **지금 저장** 버튼과 **마지막 저장 시각**이 표시됩니다.
3. **지금 저장**이 끝난 뒤 정상 종료하고 다시 접속하면 캐릭터와 누적 처치 수가 유지됩니다.
4. 플레이 중에는 10분마다 저장하며, 저장 후 공용 랭킹에도 기록이 반영됩니다. +9/+10 강화와 90/99레벨 축하 알림은 달성 직후 저장을 시도합니다.
5. 채팅은 실시간으로 유지됩니다. 채팅이나 저장 연결이 끊겨도 사냥은 계속되고, 저장 실패는 별도로 안내합니다.

**종료 전 지금 저장을 눌러주세요.** 정상적인 시작 화면 이동·로그아웃은 저장을 기다리지만, 탭을 강제로 닫거나 새로고침할 때의 마지막 저장은 브라우저가 보장하지 않습니다. 마지막 저장 이후 진행이 사라질 수 있습니다. 저장 실패 안내가 있으면 인터넷 연결을 복구한 뒤 다시 저장하세요.

이 버전은 브라우저에서 진행을 계산하는 방식입니다. 계정별 데이터 분리와 저장 충돌 방지는 유지하지만, 자기 진행 수치를 조작하는 행위까지 서버가 검증하지는 않습니다. 같은 계정의 여러 창을 동시에 사용하지 마세요. 충돌 시 **서버 기록 다시 불러오기**는 현재 창의 저장되지 않은 진행을 버립니다.

`npm run test:e2e:online`은 실제 계정 대신 격리된 모의 인증·저장 응답으로 흐름을 검사합니다. 최신 공개 배포에서 실제 계정 두 개의 저장·랭킹·채팅 확인은 별도로 진행해야 합니다.
